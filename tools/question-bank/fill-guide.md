# 「수학 문제」 단원 채우기 — 일하는 법

초등 수학 문제은행(`learning/literacy-numeracy/math-bank/`)의 한 단원에, 수집본에서 뽑아 둔 **꼴 목록의 꼴을 빠짐없이 문항으로** 옮기는 일이다.
꼴 목록에는 단원마다 꼴이 100개 넘게 있다. **꼴 목록의 꼴 하나하나를 문항으로 싣고, 빼는 것은 까닭이 분명한 것뿐**으로 한다. 단원을 다 쓰고 문항이 꼴 수의 절반에도 못 미치면 덜 쓴 것이다.

## 1. 일할 곳
- 네 작업 폴더(사본): 과제 글에 적힌 `…/fill/<단원>/math-bank`. **이 폴더 안의 `units/<단원>c.js` 하나만 새로 쓴다.** 그 밖의 파일(엔진·다른 단원·검사)은 고치지 않는다. 저장소 원본(`learning\…`)도 건드리지 않는다. git 명령은 쓰지 않는다.
- 꼴 목록(읽기 전용): `references\textbooks\수학\_분석\<단원>\기본꼴_1.md, 기본꼴_2.md, 기본꼴_3.md, 심화꼴.md`(단원에 따라 `기본꼴_통합.md`가 있으면 그것도). 수집본은 출판사 저작물이라 **문장을 그대로 옮기지 않는다** — 꼴(무엇을 주고 무엇을 묻는가)만 가져오고 수와 상황은 새로 쓴다.
- 먼저 읽을 것: 작업 폴더의 `units/<단원>a.js`(기본), `units/<단원>b.js`(실력) — 이미 실린 유형과 그 `ref`(①n = 기본꼴_1의 n번, ②n, ③n, 심n), 머리 주석의 「뺀 것과 까닭」. 그리고 `engine.js`의 `B.kit`(그림·문항 도구), `geometry.js`(도형), 검사 `tests\math-bank-units.test.cjs`(어떤 `facts`를 다시 셈해 주는지).

## 2. 무엇을 싣는가
꼴 목록 넷을 처음부터 끝까지 읽고, **이미 실린 유형이 묻지 않는 꼴은 모두 새 유형으로** 쓴다. "하는 일이 다르면 다른 문제"다:
- 주는 것(식·그림·표·수직선·문장), 묻는 것(값·고르기·차례·맞는 것/틀린 것·빈칸), 계산 구조(받아올림 유무, 자리 수, 0이 끼는가), 문장제의 얼개(합치기·덜어 내기·비교·몇 배·두 번 계산)가 다르면 다른 꼴이다.
- 꼴의 「변형」에 적힌 것도 하는 일이 다르면 따로 싣는다.
- 숫자만 다르거나 상황(이름·물건)만 다른 것은 한 번만 싣는다. 이미 실린 유형과 그런 관계면 싣지 않는다.

**빼는 것은 아래뿐**이고, 뺀 꼴은 번호와 까닭을 보고에 적는다.
1. 상위 학년의 특정 단원 내용(예: 둘레·넓이 5학년, 약수와 배수 5학년, 통분 5학년, 두 자리 수로 나누기 4학년, 등식의 성질·방정식 꼴, 경우의 수, 비례). 출판사가 그 학년 심화로 실었다는 것은 근거가 아니다. 문제마다 "몇 학년 무슨 단원 내용인가"를 따진다. 긴가민가하면 빼고 까닭에 적는다.
2. 긋기·그리기·색칠하기(작도), 식·까닭·방법 쓰기(서술형), 문제 만들기, 놀이·활동, 앞 학년 되짚기.
3. 어려움이 그 단원 내용이 아니라 조건 풀이·경우 따지기·퍼즐에서 오는 것(합과 차로 두 수 찾기, 조건 여럿을 맞추는 수, 수 카드로 "모두 만들기", 군데군데 가려진 셈). 단, 수 카드로 가장 큰 수 하나를 만들어 계산하는 정도는 싣는다.
4. 뜻 없는 셈(빈칸에 들어갈 수끼리 더하기, 두 몫의 합).
5. **영역이 다른 문제.** 단원마다 교육과정의 어느 영역·성취기준인지를 먼저 적고, 그 영역의 일을 시키는 문제만 싣는다. 출판사 자료는 도형 단원에 측정 문제를 섞어 놓는다(2026-10-12 사용자: "이 단원이 측정영역 맞냐고. 도형영역 아니냐. 교사들이 이런 걸 잘 모르니까 니가 잘 걸러 내라고 했잖아").
   - 도형 단원(삼각형·사각형·다각형·합동과 대칭·입체도형)에는 뜻, 구성 요소, 분류, 성질 그 자체를 싣는다. 성질은 **한 도형에 한 번 바로 대는 것**까지만 싣는다(이등변삼각형의 크기가 같은 두 각, 평행사변형의 마주 보는 각, 대응각).
   - 각도를 더하고 빼며 이어 가는 문제는 「각도」 단원(측정)의 일이다. 도형을 이어 붙이거나 직선·원·대각선을 덧대어 각을 좇는 문제는 중학교 「삼각형·사각형의 성질」「평행선의 성질」 꼴이므로 싣지 않는다(정사각형에 정삼각형을 붙이고 선분을 그어 각 구하기, 평행선 사이의 꺾인 각, 원 안의 이등변삼각형 둘, 정오각형의 대각선이 만드는 각).
   - 교육과정의 「성취기준 적용 시 고려 사항」에 "다루지 않는다"고 적힌 것도 뺀다(예: 3~4학년 「여러 가지 사각형 사이의 관계는 다루지 않는다」, 「돌리고 뒤집기 등 복잡한 변화를 지양한다」). 원문은 `references/moe/2022-revised-curriculum/extracted/08-mathematics.txt`.
6. 지금 있는 그림 도구로 그릴 수 없는 그림이 꼭 필요한 꼴 → 「그림이 필요해 미룬 꼴」에 번호와 필요한 그림을 적는다(억지로 글로 풀어 쓰지 않는다).

실력(`level: '실력'`, 묶음 `hard`)에는 심화꼴 가운데 학년에 맞는 것만 싣는다. 남길 것은 둘뿐이다.
- ① **문제의 상황·그림에 함정이 있어, 그 단원에서 배운 뜻을 정확히 대야 풀리는 문제.** 어려움은 보기가 아니라 문제의 장치에서 나와야 한다. 본보기: 비스듬히 놓인 정사각형을 섞어 놓고 「직사각형은 몇 개인가」, 길게 그린 선분과 짧게 그린 직선, 눈금 2에서 시작한 자로 잰 길이, 같은 떡을 3조각·8조각으로 나눠 한 조각씩 먹은 두 사람. 보기를 쓸 때는 보기마다 "어떤 아이가 고르는가"를 주석으로 단다.
- ② **두 번 넘게 생각해야 풀리는 문제**(여러 단계 문장제, 거꾸로 구하기, □의 범위, 어떤 수를 구해 바르게 계산하기).
- **실력이 아닌 것**: 기본에서 이미 하는 일(계산 한 번, 뜻·이름 되묻기, 값 하나 읽기, 단위 한 번 바꾸기)을 고르기로 바꾸고 틀린 보기에 흔한 실수 답을 넣은 것. 「바르게 계산한 것은? 3 1/5 − 1 3/5 + 보기 넷」「302 × 3의 값은? + 보기」가 그런 문항이다(2026-10-12 사용자: "이게 무슨 실력이야"). 같은 일을 하는 기본 유형이 이미 있으면 싣지 않고, 없으면 기본 묶음에 싣는다. 한 번 계산하면 되는 것은 기본이다.

## 3. 파일 쓰는 법
`units/<단원>c.js`는 a.js와 같은 틀로 쓴다.
```js
// <단원> — 꼴 목록을 다시 대조해 보탠 문항.
(function (root) {
  'use strict';
  const B = root.MathBank;
  const { josa, N, M, C /* … */ } = B.kit;
  const T = (id, title, ref, make, more) => Object.assign({ id, level: '기본', title, source: '수집본 기본 자료(' + ref + ')', make }, more || {});
  const H = (id, title, ref, make, more) => Object.assign({ id, level: '실력', title, source: '수집본 심화 자료(' + ref + ')', make }, more || {});
  B.addTypes('<단원>', '<묶음 id>', [ T('…', '…', '①12 ②8', (d) => { … }), … ]);   // 있는 묶음에 보태기
  B.addGroup('<단원>', { id: '…', title: '…', standard: '4수01-06', types: [ … ] });   // 꼭 필요할 때만 새 묶음
  B.addTypes('<단원>', 'hard', [ H('…', …) ]);
})(typeof window !== 'undefined' ? window : globalThis);
```
- 유형 id는 단원 안에서 겹치지 않게(a.js·b.js의 id와도). 성취기준(`standard`)은 a.js에 쓰인 것 가운데 고른다(유형마다 `{ standard: … }`로 바꿀 수 있다).
- `make(d)`는 씨앗 난수 `d`(`d.int(a,b)`, `d.pick(list)`, `d.shuffle(list)`, `d.bool()`, `d.until(만들기, 조건)`)로 수를 골라 문항 하나를 돌려준다. **어떤 씨앗에서도** 조건을 만족하는 수가 나와야 한다(`d.until`이 못 찾으면 실패한다 — 조건이 빡빡하면 결과부터 정하고 거꾸로 만든다).
- 문항 꼴: `N(글, 답, o)` 수 하나 · `M(글, [{label, answer, unit}], o)` 수 여럿 · `C(글, 보기[], 정답 자리, o)` 고르기 · `F(글, 분자, 분모, o)` 진분수(더 줄일 수 없는 것만) · `D(글, 답, o)` 소수 한 자리. `o`: `{ figure, unit, lead, explain, facts }`. **식·설명을 쓰게 하는 문항은 만들지 않는다(단답·객관식만).**
- 고르기 문항의 보기는 서로 달라야 하고 정답은 하나뿐이어야 한다. 정답 자리는 `d.shuffle`로 섞는다. 수의 크기·순서로 답이 뻔히 보이지 않게 한다.
- **`facts`는 꼭 넣는다**(검사가 답을 다른 길로 다시 셈하는 근거). 두루 쓰는 것:
  - `calc: [[식 글, 답 칸 번호], …]` — 식은 숫자와 `+ - * / % ( )`만. 몫은 `(a-a%b)/b`, 나머지는 `a%b`. **식에 쓴 수는 문제 글·그림·보기에 적힌 수여야 한다.** 글에 숫자로 없는 수(1000, 60, 2 따위)는 `unseen: [1000]`에 밝힌다. 그림 속 수는 그 그림의 `aria-label`에 적혀 있어야 읽힌다. 식의 값은 0보다 커야 한다.
  - `choose: { exprs: [보기 차례대로 식 글], rule }` — rule: `'compare'`(보기 [>, =, <]), `'max'`, `'min'`, `'equals'`(+`target`), `'nearest'`(+`target`), `'onlyAbove'`/`'onlyBelow'`(+`target`).
  - `truth: [보기마다 참/거짓], want: true|false` — 참(거짓)인 보기가 하나뿐이고 그것이 답.
  - `claimed: [[식 글, 문제에 적힌 값], …], claimedWant: true|false` — 식의 값이 적힌 값과 같은(다른) 것이 하나뿐.
  - `pick: { expr, options }` — 수 보기 가운데 식의 값과 같은 것이 답. `only: { values, test: 'atLeast'|'atMost', target }`. `between: { low, high, exprs }`. `rank: { values, nth }`.
  - 단원에 따라 더 있다(검사 파일에서 `if (f.` 를 찾아본다). 새 검사 규칙은 만들 수 없으니 위의 것으로 적는다.
- 같은 꼴 검사: 수를 `#`로 바꾼 글(text+figure의 글)이 단원 안의 다른 유형과 같으면 검사가 떨어진다. 묻는 말을 다르게 쓰거나, 계산 구조만 다른 계산 문항이면 `facts.rule`에 서로 다른 이름(문자열)을 단다.

## 4. 글 쓰는 법(사용자가 정한 것)
- **수능 문체.** `~세요/~습니다/~인가요/~해요` 금지. 풀이도 `~이다`. 값·수를 물으면 「~은?/~는?」, 양을 물으면 「몇 ~인가?」, 시키는 말은 「다음을 계산하시오.」.
- **수와 단위 기호는 띄어 쓴다**: `3 cm`, `2 L 300 mL`, `1 kg 500 g`, `□ mm`. 우리말 단위는 붙인다: `5개`, `3명`, `20분`.
- 토씨는 `josa(값, '은/는' | '이/가' | '을/를' | '과/와' | '으로/로')`로 붙인다(수는 읽는 소리대로 붙는다). 사람 이름은 `NAMES`에서 고르고 `name(이름, '은/는')`. 단위 기호 뒤 토씨는 읽는 소리대로 직접 적는다(mL·L·m·cm → 는/를/가, g·kg·t → 은/을/이).
- 아이가 쓰는 낱말로. 「견주다」 대신 「비교하다」. 한자말·어려운 말을 피한다. 문장제 상황은 흔한 것(구슬·색종이·사탕·책·끈)으로 새로 쓴다. 실제 사람·학교 이름은 쓰지 않는다.
- 풀이(`explain`)는 한두 문장으로 어떻게 구하는지 적는다. 답이 왜 그것인지가 보여야 한다.
- 그림은 `B.kit`와 `B.kit.geo`에 있는 것만 쓴다(a.js가 쓰는 것을 본다). 휴대폰 너비(360px)를 넘는 가로로 긴 표·식은 쓰지 않는다(표는 세로로).

## 5. 확인(모두 통과할 때까지 고친다)
작업 폴더를 `D`라 하면(예: `…/fill/3-2-4/math-bank`), 저장소 뿌리에서:
```bash
MATH_BANK_DIR="D" node tools/question-bank/tryseeds.cjs <단원>          # 유형마다 씨앗 60개: 「끝」만 나오면 통과
MATH_BANK_DIR="D" node --test tests/math-bank-units.test.cjs 2>&1 | grep -E "^ℹ (pass|fail)|AssertionError|Error:" | head -20
MATH_BANK_DIR="D" node tools/question-bank/dump.cjs <단원>              # 문항을 글로 펼쳐 본다
```
- 검사 일곱 개가 모두 pass여야 한다.
- 펼친 글을 **한 문항씩 읽고** 고친다: 답이 맞는가(직접 풀어 본다), 보기 가운데 답이 하나뿐인가, 문제 글이 답을 흘리지 않는가, 토씨·띄어쓰기·문체가 맞는가, 상위 학년 내용이 아닌가, 이미 있는 문항과 수만 다른 것이 아닌가.

## 6. 보고(짧게)
- 새로 쓴 유형 수(기본 몇, 실력 몇)와 단원의 문항 수(`dump.cjs` 끝줄).
- 꼴 대조표: 꼴 목록의 묶음별로 「실은 것(꼴 번호 → 유형 id)」, 「이미 있던 것」, 「뺀 것과 까닭」(번호와 한 줄 까닭), 「그림이 필요해 미룬 꼴」(번호와 필요한 그림). 이 대조표는 `references\textbooks\수학\_분석\<단원>\채우기_대조표.md`에도 적어 둔다.
- 확인 명령의 마지막 결과(통과 여부). 통과하지 못한 채 끝내지 않는다. 못 고친 것이 있으면 그 유형을 지우고 보고에 적는다.

## 7. 받아서 올리는 쪽이 할 일
- 사본의 `units/<단원>c.js`를 원본에 옮기고 위 확인 셋을 원본에서 다시 돌린다.
- `node tests/math-bank-browser.cjs --shots`로 모든 회차를 두 너비로 찍고, `python tools/question-bank/shot_sheet.py <그림> <시작 y> <끝 y> <나눌 수> <나올 이름>`으로 잘라 새 그림을 눈으로 본다(가려진 선, 겹친 이름표, 휴대폰 너비 넘침).
- 꼴 목록의 제목을 `grep -E "^(## |### )"`로 뽑아 대조표와 맞춰 보고, 까닭 없이 빠진 꼴은 `python tools/question-bank/forms.py <단원> 기본꼴_1:3,6 심화꼴:22`로 꺼내 읽어 마저 싣는다.
- `index.html`에 `units/<단원>c.js` 줄을 넣고 `?v=`와 단원 `version`을 올린 뒤 경로를 적어 커밋한다.
