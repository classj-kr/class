# 「수학 문제」 새 단원 짓기 — 일하는 법

아직 없는 단원을 꼴 목록에서 처음부터 짓는 일이다. **먼저 같은 폴더의 `fill-guide.md`를 끝까지 읽는다.** 거기 적힌 것(무엇을 싣고 빼는가, 문항 쓰는 법, 글 쓰는 법, 확인, 보고)은 그대로 따르고, 이 글은 다른 점만 적는다.

## 1. 쓰는 파일
작업 폴더(사본) 안에 두 파일을 새로 쓴다. 그 밖의 파일(엔진·다른 단원·검사)은 고치지 않는다.
- `units/<단원>a.js` — 단원 틀과 기본 문항.
- `units/<단원>b.js` — 나머지 기본 문항(있으면)과 실력 문항.

본보기는 `units/4-1-1a.js`, `units/4-1-1b.js`이다(읽기만). a.js가 `B.addUnit({ id, grade, semester, no, title, version: 1, groups: [...] })`으로 단원과 묶음을 모두 만들고, b.js가 `B.addTypes(단원, 묶음 id, [...])`로 뒤쪽 묶음을 채운 다음 `B.addGroup(단원, { id: 'hard', title: '실력 문제', standard, types: [...] })`로 실력 묶음을 맨 끝에 붙인다. 기본 문항이 적으면 a.js에 다 쓰고 b.js에는 실력만 써도 된다.

- 묶음은 「배우는 내용」으로 나눈다(차시가 아니다). 꼴 목록의 `## 가. …` 묶음이 좋은 출발점이다. 묶음 id는 짧은 영어 낱말, 유형 id는 `묶음-내용` 꼴로 단원 안에서 겹치지 않게 쓴다.
- 성취기준(`standard`)은 과제 글에 적힌 것 가운데 고른다. 묶음에 하나 적고, 다른 유형만 `{ standard: … }`로 바꾼다.
- 파일 머리 주석에 「싣는 기준」과 「뺀 것과 까닭」(꼴 번호와 함께)을 적는다. 실력 파일 머리에는 이 단원에서 아이들이 흔히 잘못 아는 것을 먼저 적는다.
- 문항 수는 미리 정하지 않는다. 꼴 목록의 꼴 하나하나를 문항으로 옮기면 단원마다 100개 안팎이 된다. 다 쓰고 문항이 꼴 수의 절반에도 못 미치면 덜 쓴 것이다.

## 2. 그림
- 먼저 `engine.js`의 `B.kit`와 `geometry.js`의 `B.kit.geo`에 있는 도구를 쓴다.
- 없는 그림은 단원 파일 안에 작은 함수로 그린다(`units/4-1-1b.js`의 `bigLine`, `units/3-2-3a.js`의 그림 도우미가 본보기). `styles.css`에 이미 있는 class(`mb-axis`, `mb-axis-label`, `mb-numberline`, `mb-table`, `mb-lines`, `mb-numbers`, `mb-cards`, `mb-versus` …)를 쓰고, 새 CSS가 필요하면 그 요소에만 `style="…"`로 적는다(SVG 글씨 크기는 class의 CSS가 속성을 이기므로 `style="font-size:15px"`처럼 적어야 먹는다).
- SVG에는 `role="img"`와 `aria-label`을 달고, 그림 속 수는 `aria-label`에 적는다(검사가 그 글로 식의 수를 맞춰 본다).
- 화면 검사가 떨어뜨리는 것: 너비 60px 미만·높이 20px 미만인 그림, 휴대폰 너비(360px)를 넘는 그림·표·식. 칠이 있는 도형을 나중에 그리면 먼저 그린 선이 가려진다(큰 것부터 그리고, 겹치는 선은 한 번 더 긋는다). 이름표가 선과 겹치지 않게 놓는다.

## 3. 검사
- 확인 명령은 `fill-guide.md` 5와 같다. 여기에 같은 꼴을 한꺼번에 찾는 도구를 더한다: `MATH_BANK_DIR="D" node tools/question-bank/shapes.cjs <단원>` (「끝」만 나오면 통과).
- 검사 파일(`tests/math-bank-units.test.cjs`)은 고칠 수 없다. 답을 다시 셈하는 근거는 있는 `facts`로 적는다(`calc`, `choose`, `pick`, `truth`, `claimed`, `rank`, `between`, `only` …). 큰 수·수 카드·□ 채우기에는 `facts.big`(`shown`, `written`, `names`, `odd`, `oddNames`, `boxed`, `boxedPair`, `cardsMake`, `zeros`, `countIf`)도 쓸 수 있다(검사 파일의 「큰 수」 부분).
- 참·거짓만 적는 `truth`는 검사가 답을 다시 셈하지 못한다. 그런 유형은 참·거짓을 손으로 적지 말고 코드로 계산하여 넣고, 따로 여러 씨앗으로 직접 풀어 확인한다.
- 답이 네 자리를 넘는 단원은 검사의 `BIG_NUMBER_UNITS`에 들어 있어야 한다. 넘어야 하면 보고에 적는다(받는 쪽이 넣는다). 사본 검사에서는 그 유형만 빼고 통과시킨 뒤, 뺀 유형을 보고에 적는다.

## 4. 보고
`fill-guide.md` 6과 같되, 대조표는 `references/textbooks/수학/_분석/<단원>/싣기_대조표.md`에 적는다. 보고에는 묶음별 문항 수, 뺀 꼴과 까닭(묶어서), 그림이 필요해 미룬 꼴, 새로 만든 그림 함수, 검사 파일에 넣어야 할 것(있으면), 확인 명령의 마지막 결과를 적는다.

## 분수로 답하는 문항
- 분수 하나를 답하는 문항은 `F(글, 분자, 분모, { whole, improper, unit, anyForm, explain, facts })`로 만든다. 적어 두는 답은 언제나 기약분수다(검사가 본다).
- **5·6학년 분수 계산에서는 문제 글이 「기약분수로 나타내시오」라고 하지 않았으면 `anyForm: true`를 준다.** 교육과정 원문: 「분수의 사칙계산에서 기약분수로 나타낼 것을 요구하지 않을 경우, 계산 결과를 기약분수가 아닌 분수로 나타내는 것도 허용한다.」 `anyForm`이면 크기가 같은 분수를 모두 맞게 친다(대분수는 자연수 칸이 같고 분수 부분이 진분수여야 한다).
- 약분하기·기약분수로 나타내기처럼 기약분수 자체가 답인 문항은 `anyForm`을 주지 않는다.
- 통분은 공통분모를 문제가 정해 주거나(「분모의 곱을 공통분모로」「가장 작은 공통분모로」) 답 칸이 하나로 정해지게 낸다. 원문: 「공통분모로 최소공배수뿐만 아니라 분모의 곱과 같은 공배수도 이용하게 할 수 있다.」
