# 한국지도 대개편 제안 — 물길·바람·생활을 연결하는 지도

작성: 2026-09-20. 상태: **개편 설계 제안**. 이 문서의 흐름·계절 기능은 아직 구현하지 않았다. 이번에 별도로 수행한 구현은 유물 표식 클릭 오류 수정이다.

## 판단

강물과 바람은 한국지도에서도 보여 주는 것이 맞다. 다만 각각의 움직임이 관찰할 내용과 조작할 조건을 가져야 한다. 목표는 학생이 지도를 움직이고 계절을 바꾸면서 “왜 이곳이 이렇게 되었는가”를 알아내는 지도다.

학생 흐름은 **장소 선택 → 관찰 → 조건 변경 → 이유 설명 → 문제 또는 답사**로 통일한다. 지도 위에서 본 현상과 옆의 설명·문제가 서로 다른 이야기가 되지 않게 한다.

## 실제 코드에서 확인한 출발점

- 한국지도는 Leaflet, 세계지도는 MapLibre를 사용한다. 세계지도 코드를 그대로 붙이는 것은 불가능하지만 경로를 따라 움직이는 입자와 선택 강조의 표현 방식은 공유할 수 있다.
- 한국지도에는 major-rivers.geojson, 지류 자료, 지형 타일, DEM 높이 자료, 지형 단면도 기능이 있다. 하천은 현재 굵기가 달라지는 정적 선이며 바람의 경로·계절 상태·애니메이션은 없다.
- 세계지도의 flow-textures.mjs는 경로 누적 거리로 입자를 움직인다. app.js는 바람·해류 입자를 20Hz로 갱신하며 선택한 강에 흐르는 무늬를 적용한다. 비활성 문서와 동작 줄이기 설정에서는 움직임을 멈춘다.
- 한국지도 app.js에 지도 생성, 레이어, 문제, 단면도, 상태 관리가 함께 있다. 새로운 움직임을 이 파일에 계속 추가하지 않고 분리해야 한다.
- 기존 308개 여행 장소, 68개 유물, 28개 학습 개념과 기존 195개 학습 문항은 유지한다. 기존 ID·기록 저장 형식을 개편과 함께 무심코 변경하지 않는다.

### 조작부 원칙

- 기존 주제 접근은 유지하되 각 주제에서 필요한 장면만 보여 준다. 바람·물길·유물을 처음부터 전부 켜지 않는다.
- 지도 옆은 선택한 장소 하나의 설명·그래프·관찰 질문에 집중한다. 설명 위에 또 설명하는 안내 문구를 쌓지 않는다.
- 관련된 주제로 이동할 때 선택 지역·지도 위치를 유지한다. 별도 앱으로 이동한 것처럼 매번 초기화하지 않는다.
- 긴 설명을 읽거나 문제를 풀 때는 움직임을 일시 정지할 수 있게 한다. 문제에서 답을 드러내는 강 이름·흐름·지역 강조는 제출 후 공개한다.
- 본문·문제·선지·해설은 사용자가 선택한 KoPubWorld 바탕체를 유지한다. 조작 버튼은 구별이 쉬운 UI 글꼴을 유지한다.
- 모바일은 하단 상세 패널을 사용하더라도 닫기·뒤로·현재 위치가 항상 접근 가능해야 한다. 유물의 실제 위치와 겹침을 피하려 옮긴 표식은 연결선으로 구분한다.

## 과학적으로 먼저 해결할 것

### 하천

현재 선의 좌표 배열 순서가 곧 흐르는 방향이라는 보장은 없다. 먼저 본류·지류별 시작점, 합류점, 하구와 연결 관계를 확인하고 방향 메타데이터를 만든다. 하구와의 직선거리만으로 모든 구간의 방향을 정하면 곡류나 복잡한 지류에서 틀릴 수 있다.

전체를 한번에 움직이기보다 선택한 강과 연결 지류부터 시작한다. 기존 하천의 굵기 추정값을 실제 유량으로 소개하지 않는다. 유역 경계는 DEM 또는 검증된 유역 자료가 준비되기 전에는 임의 다각형으로 만들지 않는다.

### 바람·계절·강수

계절풍 장면은 계절의 대표적인 모형이고 지역 그래프는 관측 기반 평년값이다. 서로 다른 자료의 성격을 작은 범례에서 구분한다. 애니메이션 속도를 실제 풍속으로 오해하게 하지 않는다.

기상청은 한국의 주 풍계를 겨울 북서풍, 여름 남서풍으로 설명하고, 지역별 기후 자료를 별도로 제공한다. 따라서 전국에 동일한 화살표 하나를 놓고 모든 지역의 강수·눈까지 설명해서는 안 된다. 지역 장면별로 공기의 이동과 산지·해양의 역할을 검토한다. [기상청 한국 기후특성](https://www.weather.go.kr/w/climate/statistics/korea.do), [지역별 기후특성](https://www.weather.go.kr/w/climate/statistics/region.do)

평년값의 기준 기간을 표시하고, 남북한 자료의 기간·관측망 차이를 확인한다. 근거가 없는 북한 상세 수치는 남한 값으로 메우지 않는다. 강수량을 바람 입자 수와 기계적으로 연결하거나 정밀한 일기예보처럼 보이는 모의실험을 만들지 않는다.

### 해안·생활

해류와 조류·조석은 서로 다른 현상으로 나눈다. 해류 경로와 방향은 출처 확인 후 그린다. 인구·교통의 움직임은 시간·물동량·이동량 자료가 있을 때만 수치와 연결한다. 실제 자료가 없는 자동차나 사람이 반복 이동하는 효과를 통계처럼 보여 주지 않는다.

## 기술 구조

추천은 **기존 한국지도 엔진과 자료는 보존하고, 상태 관리와 동적 표현 계층을 분리하는 것**이다. 바람 효과를 위해 바로 지도 엔진 전체를 교체하지 않는다. 향후 실제 3D 지형이 수업에 필요해지면 별도 평가한다.

예상 구성:

- scene-state.js: 주제, 계절, 선택 지역, 재생 상태, 문제의 정답 공개 상태.
- flow-layer.js: Leaflet 좌표 투영을 사용하는 전용 Canvas 흐름 레이어. 클릭을 받지 않고 표식 아래에 배치.
- flow-data.js: 방향이 검증된 하천 경로와 계절·지역별 바람 경로, 출처·자료 성격.
- scene-controller.js: 장면 진입·이탈 시 필요한 레이어만 켜고 이벤트와 재생 루프를 해제.
- place-details.js: 여행·유물 상세창의 공통 접근성, 닫기, 스크롤, 글꼴 규칙.
- 기존 study.js와 문제 시스템: 새 장면 상태를 입력받되 답 공개 전후의 표시 정책을 따로 적용.

경로 보간·색상·정지 상태의 방향 표시 등 세계지도와 공통인 부분은 작은 순수 함수부터 공유할 수 있다. 두 지도의 투영·렌더링 API까지 억지로 같은 함수로 묶지는 않는다.

## 구현 순서와 완료 기준

1. **안정화:** 68개 유물의 실제 클릭·표식 간격·시대 필터·주제 전환 검사를 추가한다. 기존 읽기·문제·지도 이동 검사를 유지한다.
2. **첫 완성 장면:** 한강과 연결 지류의 흐름 + 여름·겨울 계절풍 + 선택 지역 두 곳 비교를 연결한다. 정지 화면, 휴대폰 조작, 관련 문제까지 하나의 흐름으로 완성한다.
3. **지형·기후 확장:** 다른 주요 하천, 검증된 유역, 산지와 단면, 지역별 바람·강수 장면으로 넓힌다.
4. **해안·생활·답사:** 근거 자료를 확보한 해안 장면부터 추가하고, 308개 장소·68개 유물의 관찰 활동과 주변 지리를 연결한다.
5. **전체 구조 정리:** 불필요한 버튼·중복 상세창을 줄이고, 기존 주제·학습 기록·URL 진입을 회귀 검사한다.

각 단계는 다음 조건을 통과한 뒤 다음으로 간다.

- 선택한 대상이 정확히 열리고, 바람·강물 레이어가 클릭을 가로채지 않는다.
- 자료 경로와 입자 방향이 일치하며, 계절 전환 뒤 이전 경로가 남지 않는다.
- 확대·축소·이동·창 크기 변경 뒤 표현이 지도에서 밀리지 않는다.
- 멈춤·동작 줄이기·비활성 탭에서 재생이 정지하고, 멈춰도 방향을 읽을 수 있다.
- 저사양 모바일에서 화면 내 입자 수를 제한한다. 목표 성능은 실제 기기·브라우저 측정으로 확정한다.
- 해설과 문제의 글꼴·행간을 유지하며, 정답을 미리 알려 주는 레이어가 나타나지 않는다.
- 사진·설명·문항·기록 데이터가 사라지거나 바뀌지 않는다.

## 이번 수정과 개편을 구분

이번 수정은 heritage.js의 표식 최종 배치 충돌 제거, 최대 확대에서 개별 표식 접근, Enter·Space 활성화와 tests/korea-map-heritage.cjs의 회귀 검사다.

위 개편은 다음 구현의 설계안이다. 실시간 날씨 연동, 전면 3D 전환, 기존 문제은행 전면 개작, 배포는 이번 승인 범위에 포함하지 않았다.
