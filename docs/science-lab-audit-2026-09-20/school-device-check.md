# 크롬북·아이패드 우선 검사

휴대전화가 아니라 크롬북의 키보드·포인터 사용과 아이패드의 터치·가로세로 사용을 우선 기준으로 삼는다. 화면 폭만 바꾼 Chrome 검사와 별도로 Windows Playwright WebKit에 터치 입력을 설정한 검사를 추가했다.

## 변경

- 기존 확인 문제를 펼치는 영역과 선택지 라벨의 높이를 최소 44px로 확대했다. 선택지 글자뿐 아니라 라벨 영역을 눌러 선택한다.
- 조작 버튼의 최소 너비를 44px로 두고 버튼·펼치기 영역에 `touch-action: manipulation`을 적용했다. 화면 전체의 확대를 막는 설정은 넣지 않았다.
- 설명·문제의 명조체와 간결한 문제 화면은 유지한다.

## 재현 검사

- `tests/science-school-devices.test.cjs`: WebKit 터치 환경의 104개 앱 로딩과 앱별 첫 문항 정답 선택, 주요 터치 영역 크기. Chrome의 Tab·Enter·Space 입력, WebKit의 실제 합성 touchstart 이벤트, 답안 선택 후 화면 크기 변경, 이전·다음 이동, 초기화와 초점 이동.
- 크롬북 재현 화면: 1366×768, 1280×720, 1093×614. 마지막 값은 사용 가능한 CSS 영역이 줄어든 상황이며 실제 ChromeOS 화면 확대 설정을 조작한 검사는 아니다.
- 태블릿 재현 화면: 820×1180, 1180×820, 768×1024, 1024×768, 744×1133. 창 크기 변경 후 문제·답안 상태를 유지하는지 확인한다.
- `tests/science-tablet-experiments.test.cjs`: 24개 필수 실험의 조건 선택 자동화, 터치 정답 확인·관찰 기록·초기화, 가로세로 크기 변경 후 조건과 화면 유지.
- `tests/science-visual-layout.test.cjs`: 공통 UI와 주요 15개 실험의 Chrome 레이아웃 회귀 검사.

## 검증 경계

이 검사는 실제 ChromeOS 하드웨어나 실제 iPad의 Safari가 아니다. Windows WebKit은 Safari 계열 엔진의 추가 호환성 점검에 이용한 테스트 브라우저다. iPadOS의 네이티브 선택창·주소창·분할 화면·실제 핀치 확대, 기기별 성능과 마이크 권한, 실제 트랙패드 감도는 실기 확인 대상으로 남는다. 마이크를 사용자 허가 없이 켜거나 실측했다고 주장하지 않는다. 코드 반영과 배포도 별개다.

실행 시 로컬 Playwright 및 WebKit 설치가 필요하다. Chrome 검사는 `SCIENCE_BROWSER`로 실행 파일을 지정하고 `NODE_PATH`에 작업 런타임의 패키지 경로를 지정한다.
