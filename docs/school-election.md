# 전교 임원선거

교직원 메뉴의 **학급선거**는 기존 /vote/로 연결되고, 새 **전교 임원선거**는 /school-election/?mode=teacher로 연결됩니다. 두 기능은 별도 테이블과 흐름을 사용합니다. 모든 선거 참여에는 계정 로그인이 필요합니다.

## 운영 흐름

1. 담당 교사가 명단 학년도, 투표 대상 학년(화면은 초등 1~6학년), 직책과 후보를 입력합니다. 기본 대상은 3~6학년입니다.
2. 준비 상태에서 통합 명단(school_students)의 학년·반별 인원과 계정 오류를 확인합니다. 계정 이메일이 없거나 중복되거나 연결 계정과 불일치하면 시작할 수 없습니다. 교사가 확인한 뒤 명단 또는 후보 설정이 바뀌면 다시 확인해야 합니다.
3. '명부 확정하고 투표 시작'을 누르면 당시 명단을 복사하여 고정합니다. 명부에 이메일만 있고 아직 로그인하지 않은 학생은 해당 이메일의 계정으로 로그인하여 참여할 수 있습니다. 선거 도중 원본 명단을 변경해도 확정 명부는 바뀌지 않습니다.
4. 학생은 메인의 방번호 입력에서 4자리 번호를 입력하거나 학생용 링크로 입장합니다. 학급선거와 다른 방의 번호를 확인한 뒤 겹치지 않는 번호를 발급합니다.
5. 담당 교사는 학년·반별 참여 인원과 선택한 반의 투표 여부만 확인합니다. 진행 중 후보별 득표수는 API에도 포함되지 않습니다.
6. 마감하면 담당 교사만 개표 결과를 확인할 수 있습니다. 결과 공개를 누른 뒤부터 확정 명부의 학생에게도 결과가 보입니다. CSV로 결과를 저장할 수 있습니다.
7. 마감하거나 결과를 공개한 선거는 만든 교사와 해당 학교 관리자가 삭제할 수 있습니다. 만든 교사는 선거 결과 화면이나 목록에서, 관리자는 '학교 전교선거' 목록에서 '선거 데이터 삭제'를 누른 뒤 방번호를 입력합니다. 해당 선거의 설정·확정 명부·투표지·진행 기록이 함께 삭제되며 앱에서 복구할 수 없습니다. 필요한 결과는 담당 교사가 미리 CSV로 저장해야 합니다. 학교 원본 명단과 학생 계정, 다른 선거는 삭제되지 않습니다.

현재 지원 범위는 직책 1~10개, 직책당 후보 2~20명, 선거인 1~2,000명입니다. 모든 유권자가 모든 직책에서 한 명씩 선택합니다. 단독 후보 찬반투표, 기권, 복수 선출, 학년마다 다른 투표용지는 지원하지 않습니다. 동점 처리나 당선자는 자동 결정하지 않습니다.

담당 교사는 해당 선거 생성자입니다. 설정 수정·시작·마감·결과 공개는 담당 교사만 할 수 있습니다. 시작 후에는 대상·후보 수정이나 재개를 할 수 없고 투표 중에는 누구도 삭제할 수 없습니다. 준비 중 선거는 만든 교사만 수정·삭제할 수 있습니다. 종료된 선거의 삭제는 만든 교사 또는 같은 학교의 관리자 권한(기존 교직원 유형 '관리자'·'교장'·'교감')으로 가능합니다. 관리자 목록에는 본인이 만든 선거와 같은 학교의 종료된 선거만 표시됩니다.

## 저장 및 접근

- school_elections: 선거 설정과 준비/진행/마감/공개 상태.
- school_election_voters: 선거 당시의 명부, 계정 연결 정보, 투표 완료 여부. 원본 명단 및 계정 삭제에 연쇄 삭제되는 외래 키를 두지 않아 확정 명부가 유지됩니다.
- school_election_ballots: 무작위 UUID, 선거 ID, 선택 후보만 저장합니다. 학생 ID, 선거인 ID, 제출 시각은 저장하지 않습니다.
- school_election_events: 담당자의 선거 생성·수정·시작·마감·공개 이력만 기록합니다. 투표자별 선택은 기록하지 않습니다.
- 학생의 개인 선택을 반환하는 API가 없으며, 다른 학교·제외 학년·명부 밖 계정은 투표와 공개 결과 조회가 거부됩니다.

투표권 소비와 표 저장은 하나의 DB 트랜잭션입니다. 선거 행의 공유 잠금은 다른 학생의 제출을 허용하고, 마감의 배타적 잠금은 진행 중인 제출을 기다립니다. 선거인 행 잠금은 같은 학생의 동시 제출을 직렬화합니다. 이미 제출한 요청을 재시도해도 표를 추가하지 않습니다. 저장 실패 시 완료 여부도 되돌립니다.

신원과 표 사이의 직접 연결을 저장하지 않는 애플리케이션 수준의 분리입니다. DB 관리자, 트랜잭션 로그, 트래픽 관찰까지 방어하는 암호학적 익명 투표 시스템은 아닙니다. 운영 환경에서 투표 요청 본문과 SQL 바인딩 값을 수집하는 로그를 추가하지 마세요.

## 검증과 미리보기

game-hub-server에서 개발 의존성을 설치한 뒤:

- npm run test:school-election
- npm run test:school-election:ui
- npm run preview:school-election

DB 테스트는 PGlite의 실제 PostgreSQL 엔진에서 실행합니다. 권한·명부 고정·동명이인·중복 제출·저장 실패 롤백·결과 공개 및 400명의 집계를 검증합니다. PGlite는 단일 연결이므로 테스트 어댑터가 트랜잭션을 직렬화합니다. 운영 DB의 병렬 잠금 경합이나 서버 수용량을 검증한 부하 시험으로 해석하면 안 됩니다.

브라우저 테스트는 가상 데이터로 별도의 로컬 서버를 자동 생성합니다. Windows는 설치된 Chrome을 사용하며, 다른 환경은 Playwright Chromium 설치가 필요합니다. PC 교사 화면과 390px 모바일 투표 화면, 결과 공개, CSV 다운로드와 비로그인 차단을 확인합니다.

수동 미리보기는 127.0.0.1:4179에서만 열리고 메모리 DB와 가상 계정만 사용합니다. 서버를 종료하면 가상 데이터는 사라집니다. 이 미리보기 서버는 운영에 배포하지 않습니다.

실제 운영 전 대상 학생의 학교 계정 로그인 확인과 예상 동시접속 규모의 운영 유사 환경 부하 시험이 필요합니다. 현재 플랫폼 DB 풀 설정(max: 5)은 변경하지 않았습니다. 운영 DB 마이그레이션이나 배포는 이 작업에서 수행하지 않았습니다.
