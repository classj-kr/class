# 게임 입장·대기실 UI 검토 (2026-09-26)

## 범위와 변경

- 실제 서비스 게임 32개: 멀티플레이 27개, 싱글플레이 5개. `index.html`로 진입하는 노노그램·슬라이딩 퍼즐도 목록 검사에 포함한다.
- 멀티플레이의 제목, 이름, 게임 방법, 방 만들기·참가, 입력 영역을 한 카드에 배치한다. 기존 DOM 컨트롤과 이벤트 연결은 유지한다.
- 방 연결 전에는 참가자·시작 버튼·방장용 설정을 숨긴다. 방 연결 후에는 각 게임의 설정과 참가자·시작 동작을 표시한다.
- 같은 그림 찾기·낱말 암호·원정대 추리의 별도 대기실도 폭·여백·버튼 크기를 정리한다. 같은 그림 찾기의 규칙 설명 중복을 제거한다.
- 그림 릴레이의 `CLASSROOM EDITION`, `WORD PACK`, `방장이 선택해요`와 중복 참가 안내를 소스에서 제거한다. 다른 게임의 중복 장식 부제도 정리한다.
- 체스·장기 채팅과 님게임 설정은 펼쳐서 이용한다. 싱글플레이의 시작 화면도 게임판 크기의 빈 영역을 줄인다.
- 게임 방법 창의 제목을 작게 통일하고 밝은 테마의 안내·방 번호 대비를 바로잡는다.

## 검증

- `node tests/game-entry-ui-browser.cjs`: 32개 게임의 입장·대기실(멀티플레이)·게임 방법 화면. 1366×768, 768×1024, 390×844. 가로 넘침, 분리된 참가 입력, 입장 전 시작 버튼 노출, 불필요한 문구, 과도한 도움말 제목, 자바스크립트 오류를 검사하고 스크린샷을 저장한다.
- `ROOM_TEST_ORIGIN=http://127.0.0.1:18124 node tests/multiplayer-lobby-browser.cjs`: 실제 서버에서 27개 게임의 방 생성과 다른 브라우저 참가. 세 크기의 입력 배치, 방 번호 크기·렌더링된 배경 대비. 원정대 추리·낱말 암호·같은 그림 찾기는 최소 인원 시작 및 퇴장 후 대기실 복귀까지 검사한다.
- 공통 로비 단위·적용 검사 및 방 복구 검사 통과.
- 모든 게임의 입장·대기실·게임 방법 스크린샷을 직접 비교했다. 전체 게임의 경기 종료까지 진행한 검증은 아니다.

최종 로컬 결과는 `outputs/game-entry-ui-release/`에 저장했다(32/32 통과). 실제 방 연결 검사는 `outputs/multiplayer-lobby-check/`에 저장했다(27/27 통과). 싱글플레이 5개 모두 시작 후 게임 화면 전환·가로 넘침·실행 오류도 확인했다. 운영 검증은 같은 UI 검사에 승인된 별도 게스트 세션을 사용하고 `outputs/game-entry-ui-production/`에 기록한다. 로컬의 싱글플레이 기록 서버 안내는 로컬 DB 미설정에 따른 것이므로 운영에서 별도 확인한다.
