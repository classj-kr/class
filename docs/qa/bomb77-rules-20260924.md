# 77 폭탄 규칙 및 실제 플레이 검증 — 2026-09-24

이전 방 생성·참가 검사는 게임 규칙의 충실도나 실제 재미를 증명하지 못했다. 이번 변경은 서버 규칙, 선택 결과 안내, 실제 다인 플레이를 함께 검증한다. 사용자 대상 재미 평가를 수행했다는 의미는 아니다.

## 기준과 변경

기준: [AMIGO 공식 Lobo 77 규칙 v3.2](https://blog.amigo-spiele.de/content/ap/rule/03910-DE-AmigoRule.pdf). 기존 ‘77 폭탄’ 이름과 자체 제작 그림은 유지한다.

- 55장 구성: 2~9 각 3장, 10은 8장, 11·22·33·44·55·66·76 각 1장, 0·−10·×2·방향 전환 각 4장.
- 합계 11~66의 양수 11배수는 칩 1개를 잃고 계속한다. 특수 카드로 해당 합계를 반복해도 벌칙이다.
- 77 이상은 칩 1개를 잃고 즉시 라운드를 끝낸다. 77이라고 칩을 두 번 잃지 않는다.
- ×2는 두 번 내고 각각 판정한 후 두 장을 보충한다. 첫 장에는 ×2 금지, 두 번째 장에는 허용한다. 첫 장이 방향 전환이어도 같은 사람이 두 번째 장을 낸다.
- 칩 0개는 마지막 기회이며 다음 벌칙에 탈락한다. 마지막 생존자가 승리한다.
- 다음 라운드는 전체 재분배, 시작 플레이어는 정방향 순환. 덱 재활용은 맨 위 버린 카드를 남긴다. −10은 음수까지 허용, 0은 합계 유지다.

디지털 조정: 카드 보충 자동 처리, 한 장당 25초 후 자동 선택, 폭발 결과를 3초 표시한 후 다음 라운드. 선택한 카드의 결과와 벌칙을 미리 보여주며, ×2 남은 장수·진행 방향·다음 플레이어·마지막 기회를 표시한다.

구버전 저장 게임은 복원 시 대기실로 돌려 새 규칙으로 시작하게 한다. 77 폭탄은 같은 탭 새로고침 시 방장과 참가자 모두 기존 방·손패를 복원한다. 기존 공통 로비의 기본 나가기 동작은 유지하며 `keepRoomOnReload: "all"`로 이 기능을 선택한다.

## 검증

- `node --test game-hub-server/bomb77.test.mjs game-hub-server/bomb77-ui-contract.test.mjs game-hub-server/bomb77-music-contract.test.mjs tests/multiplayer-room-recovery.test.js`: 30개 통과. 공식 예시, 벌칙 중복 방지, ×2, 탈락, 손패 비공개, 2~8인 56회 완주 및 전체 카드 수 보존 포함.
- `node tests/multiplayer-lobby-unit.js`: 공통 로비 및 새로고침 보존 옵션 통과.
- `node tests/multiplayer-lobby-adoption.js`: 멀티플레이 27개·싱글플레이 3개·템플릿 통과.
- `node tests/boardgame-motion-browser.cjs`: 77 폭탄 포함 4개 게임의 이동 애니메이션, 중복 상태 수신, 모션 감소 통과.
- `node tests/bomb77-browser.cjs`: 실제 로컬 서버, 별도 브라우저 세션 3개, 실제 무작위 손패로 방 생성·참가부터 승리·재경기까지 플레이. 모의 소켓이나 주입된 게임 상태는 사용하지 않는다.
- 브라우저 검사에는 1024×768, 768×1024, 720×900, 390×844 배치, 6회 방장·참가자 새로고침, ×2 도중 복귀, 서버 벌칙·재분배·마지막 기회·탈락·25초 자동 선택이 포함된다. 대기실 재접속과 만료된 방 복구 실패 후 새 방 생성도 통과했다. 마지막 실행은 27단계, 브라우저 실행 오류 0건이었다. 최종 결과와 화면은 `outputs/bomb77-check/`에 저장한다.

실행: 로컬 서버의 PORT=18124, ARITHMETIC_PORT=18125, WORLD_VOYAGE_PORT=18126, DATABASE_URL 비움, NODE_ENV=test. 다른 로컬 포트는 BOMB77_TEST_ORIGIN으로 지정할 수 있다. 실제 배포 서버와 PostgreSQL 재시작 복원은 이번 브라우저 검사 범위에 포함하지 않는다.

검증 당시 상태: 로컬 구현·검증 완료. 이후 사용자 배포 요청에 따라 게임 수정분을 운영 브랜치에 업로드한다.
