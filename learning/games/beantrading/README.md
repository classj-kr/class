# 콩 거래 / Bean Trading

4~5인 개인전. 방 번호로 참가하는 온라인 게임과 컴퓨터 3명이 있는 연습 모드를 제공합니다.

## 실행

저장소 루트에서 `npm start`로 기존 게임 허브 서버를 실행한 뒤 `/learning/games/beantrading/beantrading`에 접속합니다. 기본 포트는 10000이며 `PORT` 환경 변수로 변경할 수 있습니다. 메인 게임 목록에도 연결되어 있습니다.

친구들과 플레이하려면 기존 메인 화면에서 이름을 정하고, 한 명이 방을 만든 뒤 다른 사람들이 같은 방 번호로 참가합니다. 연습 모드는 이름 없이도 시작할 수 있습니다.

## 빠른 게임 규칙

- 2개의 개인 밭, 순서가 고정된 손패 5장으로 시작합니다.
- 5라운드 동안 모든 사람이 정확히 5번씩 차례를 가집니다.
- 차례마다 심기 10초, 거래 25초, 받은 콩 심기 10초입니다. 일찍 마치면 즉시 다음 단계로 갑니다.
- 최대 진행 시간은 정상적인 서버 실행 기준 4인 15분, 5인 18분 45초입니다. 대기실과 설명 시간은 별도입니다.
- 손패 맨 앞 1장을 의무적으로 심고, 두 번째 1장은 선택입니다. 서로 다른 종류는 같은 밭에 심을 수 없습니다.
- 현재 차례인 사람과만 거래합니다. 손패 어느 위치의 카드든 제안할 수 있고, 공개 카드는 현재 차례인 사람만 줄 수 있습니다.
- 제안과 수락은 별개입니다. 기부도 수락해야 성사됩니다. 제안은 각각 최대 3장까지 주고받으며, 한 사람당 동시에 최대 4개를 보낼 수 있습니다.
- 수락하면 필요한 종류를 수락자의 손패 뒤부터 선택한 뒤, 부족하면 그 사람의 공개 카드에서 가져옵니다. 중복 거래는 허용하지 않습니다.
- 받은 카드는 재거래하거나 손패에 넣을 수 없습니다. 거래가 끝나면 원하는 순서로 반드시 심습니다.
- 자기 밭은 언제든 수확할 수 있습니다. 금화가 안 나오는 수확도 가능합니다. 수확한 카드는 버린 더미로 가고 덱이 떨어지면 다시 섞입니다.
- 시간 초과 시 같은 콩 밭, 빈 밭 순서로 심습니다. 둘 다 안 되면 다음 보상까지 진행률이 낮은 밭을 수확합니다. 동률이면 첫 번째 밭을 선택합니다.
- 차례가 끝나면 손패 뒤에 3장을 받습니다. 마지막 차례에는 보충 없이 모든 밭을 수확합니다. 손패는 0점이며 금화 동점은 공동 승리입니다.
- 컴퓨터는 단순한 거래 기준으로 행동하는 연습 상대입니다. 연습 중 규칙창을 열면 시간이 멈춥니다. 온라인 게임의 규칙창은 타이머를 멈추지 않습니다.

구체적인 콩 종류별 카드 수와 수확표는 `engine.js`의 `BEANS`가 기준이며, 규칙창과 카드 화면도 이 데이터를 사용합니다. 실물 보드게임의 공식 규칙을 그대로 재현한 게임이 아닙니다. 5라운드 구성의 재미와 교실 적합성은 실제 학생들과의 플레이로 추가 조정할 수 있습니다.

## 구조 / 검증

- `engine.js`: 서버와 연습 모드가 공유하는 규칙. 온라인에서는 서버만 상태를 변경합니다.
- `game-hub-server/beantrading.js`: 서버용 진입점. 기존 허브가 방, 재접속, 스냅숏을 관리합니다.
- 손패와 제안은 당사자에게만 보내며 더미 순서는 전송하지 않습니다.
- 접속이 잠시 끊기면 기존 세션 토큰으로 복구합니다. 유예 시간 후 참가자가 이탈하면 대기실로 돌아가고, 방장이 이탈하면 방이 닫힙니다.
- `npm run test:beantrading`: 규칙 테스트, 200판 자동 완주, 실제 소켓 4인/5인 완주, 거래 동의, 비공개 정보, 재접속, 재시작.
- 실행 중인 로컬 서버에 대해 `npm run test:beantrading:ui`: 격리된 Edge 브라우저 5개로 실제 입장/거래/심기, 연습, 규칙창, 390px 모바일, 1366×768 화면을 확인합니다. 기본 URL은 `http://127.0.0.1:8936`이며 `BEAN_TEST_URL`로 변경합니다.
- 스크린샷은 Git에서 제외되는 `outputs/qa/beantrading/`에 저장합니다.

그림 목록과 제작 기록은 `assets/ART-PACK.md`에 있습니다.

공통 회귀 확인: 기존 보석 상단 서버 통합 테스트와 공통 대기실 단위 테스트를 통과했습니다. 전체 게임 브랜딩 검사는 기존 `connect6.html`의 제목 문구와 테스트 기대값이 달라 실패합니다. 해당 파일에는 이번 작업의 변경이 없습니다.
