# 연산 메뉴 재점검 — 2026-09-30

한 자리 수 덧셈·뺄셈의 마지막 두 문항에서 빈칸이 각각 0개와 2개로 나오는 제보를 계기로 연산 메뉴 176개를 다시 점검했다. 전체 입력칸 개수나 화면 정상 응답만으로는 출제·채점의 정확성을 확인할 수 없다는 점을 확인했다.

## 확인한 오류와 수정

| 학습지 | 오류 | 수정 |
| --- | --- | --- |
| 초1 한 자리 수 덧셈·뺄셈 | 29번은 빈칸이 없고 30번은 두 수가 모두 빈칸이라 답이 하나로 결정되지 않음 | 문항마다 빈칸 1개. 타입과 문항별 HTML 검사로 재발 방지 |
| 초3 시간의 덧셈·뺄셈 | 분·초 문제에서 60분 이상을 시간으로 올린 뒤 시간 칸을 표시하지 않아 정답에서 60분이 빠짐. 첫 문제지의 `41분 24초 + 41분 30초`가 `22분 54초`로 채점됨 | 표시하는 단위에 맞춰 `82분 54초`로 계산. 100분 이상 답도 입력 가능하도록 분 입력을 세 자리로 확장 |
| 초2 세로셈 빈칸 | 12문항의 24개 빈칸을 각각 정답으로 세어 일부만 맞힌 문항도 정답 수에 포함 | 한 문항의 두 자리 모두 맞혀야 1문제 정답, 총 12문제로 집계 |

시간 문제에서 시간과 함께 표시하는 분의 생성 범위도 59분까지로 맞췄다.

## 확인 범위와 결과

- `npm test`: 타입 검사, 단위 테스트 538개, 빌드, HTML 테스트 96개 통과.
- 176개 메뉴 전체의 브라우저 공통 검사 통과: 화면 연결, 빈 답 채점, 선택형 정답 선택·채점, 새 문제, 수식 표시, 인쇄 모드, 모바일 가로 넘침 등. 이 검사는 모든 주관식 문제의 정답을 독립적으로 계산하는 검사는 아니다.
- 덧셈·뺄셈 공용 화면 5종은 각각 첫 문제지와 새 문제지 2장을 실제 모바일 크기 브라우저에서 검사했다. 매 문항 빈칸이 1개인지 확인하고, 화면에 주어진 수로 답을 별도 계산해 입력하여 30/30 채점을 확인했다.
- 초2·초3 세로셈 빈칸은 각 101개 문제지, 1,212문항에 대해 가능한 숫자를 대입해 해가 정확히 하나인지 확인했다. 각 자리의 빈칸 여러 개는 이 유형의 정상 구성이다.
- 초3 시간·길이·무게와 들이, 초4 소수 덧셈·뺄셈, 초3 몫과 나머지는 각각 1,001개 문제지의 계산을 독립적으로 대조했다. 수정 전 시간 문제 769건에서 오류가 재현됐고, 수정 후 해당 표본의 계산 불일치는 0건이었다.
- 시간 화면은 첫 문제지와 새 문제지 3장에서 표시된 시간으로 답을 별도 계산하여 답지와 비교하고 직접 입력했다. 100분 이상 입력, 8/8 채점, 60분을 잘못 뺀 답의 오답 처리, 초기화를 확인했다.
- 초2 세로셈은 한 칸만 정답일 때 0/12, 두 칸 정답일 때 1/12, 전체 정답일 때 12/12, 답 수정 시 11/12, 새 문제 시 0/12를 확인했다.

## 재실행

연산앱 폴더에서 실행한다.

```text
npm test
npm run dev -- --host localhost --port 6180
npm run audit:browser
```

`scripts/audit-elementary-regressions.cjs`를 브라우저 검사에 추가했다. 기존 `ARITHMETIC_AUDIT_URL`로 다른 로컬 서버를 지정할 수 있다.

점검은 로컬 코드 기준이며 운영 사이트에는 배포하지 않았다. 전체 화면의 공통 동작과 위 계산 표본을 검증한 결과로, 모든 난수 조합이나 모든 문항의 교육적 적합성을 전수 검증한 결과는 아니다.
