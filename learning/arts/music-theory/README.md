# 음악 이론 구조

음악 이론은 별도의 중간 페이지를 두지 않는다. 메인 `index.html`의 펼침 메뉴에서 각 앱으로 직접 이동한다.

```text
메인 인덱스
└─ 음악 이론
   ├─ 리듬 트레이닝 → learning/arts/music-theory/rhythm-training/
   ├─ 청음  → learning/arts/music-theory/ear-training/
   └─ 피아노 스케일·보이싱 → learning/arts/music-theory/piano-skills/
```

## 디렉터리 책임

- `rhythm-training/`: 직접 만든 4/4박자 패턴을 한 번씩 두드리는 연습과 교사 개설 학급 순위전. 음 길이와 손을 떼는 시점은 채점하지 않는다. 악보 렌더러는 `ear-training/`을 공유한다. 모든 학생은 같은 판·속도를 사용하며 자기 기기의 네 박 준비 후 연주한다. 서버는 타격 기록을 재채점한다. 교사가 결과 화면에서 다음 판을 시작하려면 학생들이 다시 준비해야 한다. 방과 순위는 서버 메모리에 최대 2시간 보관되며 재시작 시 종료된다. 클라이언트 입력 시간을 검증 가능한 점수로 환산하지만 조작된 클라이언트까지 막는 시험용 시스템은 아니다.
- `ear-training/`: 음정·화음·음계·화음 진행·리듬·가락을 소리로 판별하는 훈련. 피아노 음원과 재생 엔진을 여기서 갖는다. 리듬은 악보를 보고 두드리기와 받아쓰기로 나뉘고, 받아쓰기는 8·16칸 정간보식 칸에서 시작해 셋잇단음표부터 악보 고르기로 넘어간다.
- `piano-skills/`: 스케일과 보이싱 연습

리듬 트레이닝의 `notation.js`와 `rhythm-notation.js` 요청은 게임 허브 서버가 청음의 공통 렌더러 파일로 연결한다. 학생에게 청음 메뉴를 열지 않아도 리듬 트레이닝의 공개 설정으로 악보 자원을 읽을 수 있다. 검증은 `node --test tests/rhythm-training.test.cjs`, `node tests/rhythm-training-browser.cjs`로 실행한다.

## 악보 고르기 보기 만드는 법

리듬 악보 고르기의 보기 넷은 **치는 자리 수가 모두 같아야** 한다. 수가 다르면 소리를 몇 번 들었는지
손가락으로 세기만 해도 답이 나온다. 그래서 보기는 정답에서 치는 자리 하나를 바로 옆으로 옮겨 만든다.
수가 그대로이고 악보도 한 군데만 달라 보이므로 어디서 치는지를 들어야 한다. 첫 박은 되도록 그대로
두어 시작을 견주지 못하게 한다.

## 악보 그리기

자리표(𝄞)와 임시표(♯ ♭ 𝄪)는 **직접 그리지 않는다.** 유니코드 글리프를 쓰되, 글꼴마다 글리프가 차지하는
자리와 크기가 달라 그냥 찍으면 오선에 맞지 않는다.

**SVG의 `getBBox()`로 재면 안 된다.** 그것은 글리프가 아니라 글꼴 줄상자를 돌려주어 ♭·♯·𝄞가 모두 같은
높이(줄 높이)로 나온다. 캔버스 `measureText()`의 `actualBoundingBoxAscent/Descent/Right`로 먹이 닿는
테두리를 재야 한다. 잰 값으로 크기를 맞추고(올림표 두 칸, 내림표 두 칸 반, 자리표 일곱 칸), 기준점을
음표 자리에 앉힌다. 자리표는 소용돌이(먹 높이의 63%)를 G선에 맞춘다. 캔버스와 SVG가 같은 글꼴을 써야
하므로 글꼴 이름은 `.sheet-glyph`의 계산된 값을 읽어 쓴다. 손으로 길(path)을 그리려 들면 지렁이가 된다.
온음표만은 글리프가 아니라 타원 둘 + evenodd로 그린다(가운데 구멍이 비스듬히 뚫린 고리).

**조표가 이미 건드린 음에는 임시표를 다시 붙이지 않는다.** 사장조에서 F♯에 ♯을 또 그리면 틀린 악보다.
거꾸로 조표가 건드린 음을 제자리로 되돌릴 때는 제자리표(♮)를 붙여야 한다 — 사장조의 ♭VII(F 장3화음)이
그 경우다. 그래서 임시표는 음의 임시표와 그 자리의 조표를 견주어, 다를 때만 그린다.

조표는 개수만 늘어놓으면 뜻이 없다. 임시표가 어느 줄과 칸에 붙는지가 조표이므로, 오선·자리표를 함께
두고 통째로 줄여서 작게 놓는다(원판 가운데 `SIG_SCALE`).

오선 길이는 칸 수가 적어도 같게 둔다(`minWidth`). 짧은 오선이 넓은 자리에 떠 보이면 망가져 보인다.

5도권 원판 가운데에는 오선을 그리지 않는다. 올림표·내림표만 작게 모아 몇 개인지 보이면 된다.
같은 소리를 다른 이름으로 적는 자리는 F♯=G♭ 하나만 둔다. 조표가 일곱 개가 되는 C♯ 장조(♯7)와
C♭ 장조(♭7)는 요즘 쓰지 않고 각각 D♭·B로 적으므로 넣지 않는다. 그 한 자리에 `F♯(G♭)`처럼 괄호로
잇대어 적고, 새 단추나 새 자리는 만들지 않는다. 어느 쪽으로 돌아 도착했느냐에 따라 이름도 조표도
함께 뒤집힌다 — ♯쪽에서 오면 F♯에 ♯ 여섯, ♭쪽에서 오면 G♭에 ♭ 여섯. 이름 뒤의 올림표·내림표는 글자와 같은 크기로
두면 자리를 너무 먹으므로 작게(.66em), 괄호 안은 더 작게(.58em) 붙인다.

보기 악보는 차시가 달라도 같은 크기여야 한다. 폭을 `viewBox` 눈금 × 배율로 못 박고(`EXAMPLE_ZOOM`),
칸 너비에 맞춰 늘이지 않는다. 위아래 여백은 음표가 닿는 데까지만 남긴다.

## 설명 차시는 한 화면

크롬북 1366×768, 아이패드 1024×768·1180×820·768×1024에서 제목·글·건반·단추가 늘 보이고 바닥이
밀리지 않아야 한다. 그 크기에 들어가는 보기는 한 차시에 셋까지다. 넷 이상이면 차시를 나눈다
(3화음 → 장·단 / 감·증, 교회 선법 → 장음계 쪽 / 단음계 쪽).

## 청음 구조

첫 화면은 **혼자 연습 · 과정 · 찾아보기** 셋이다. 연습을 누르면 **판(preset) 목록**이 나오고, 판이 곧
난이도 순서다. **준비 화면은 없다** — 문제 수는 열 개로 못 박고, 범위는 판이 정하고, 들려주는 방법은
문제 화면 안 단추로 옮기고, 답하는 방법은 판 줄의 아이콘 둘(♪ 건반 / ▤ 보기 단추)로 고른다.
방향(상행·하행)은 판을 쪼개지 않고 문제마다 무작위로 섞는다.

**판 목록은 한 줄씩 위아래로만 놓는다.** 두 칸으로 나누면 왼쪽·오른쪽을 오가며 읽어야 해서 난이도 차례가
헷갈린다. 줄이 열셋을 넘는 연습(음정 15, 리듬 16)은 크롬북 세로 768px에서 밀어 봐야 한다 — 아이콘이
44px여서 줄 높이를 그보다 줄일 수 없다. 첫 화면 카드에는 판이 몇 개인지 적지 않는다(눌러 보면 나온다).

가락 받아쓰기는 음정 연습 안에 둔다 — 음정은 두 음을 함께 듣고 가락은 한 음씩 듣는 것이라,
같은 결의 두 묶음이 된다(두 음 일곱 판 + 세 음 여덟 판).

건반으로 답할 때는 **누를 때마다 바로 채점한다.** 틀린 음을 누르면 그 건반이 곧 빨갛게 되고 그 문제는
틀린 것으로 굳지만(한 번만 센다), 문제는 끝까지 풀 수 있고 다음 자리로 밀리지도 않는다. 화음은 누르는
순서를 따지지 않고 음정·음계·가락은 따진다. 알려 준 음(뿌리음·첫 음)은 짚어 봐도 답으로 세지 않는다.

텐션 화음은 **왼손 뿌리음 + 오른손 넷**으로 놓아 큰보표에 그린다. 텐션이 하나면 5도를 넣어 자리를
메우고 둘이면 5도를 뺀다. 조표는 조가 있는 판(다이아토닉 가락, 화음 진행)에만 붙인다 — 음정·화음·음계에
붙이면 답이 새어 나간다.

## 화음 진행

**건반으로 답하게 하지 않는다.** 자리(voicing)가 하나로 정해지지 않아, 진행을 제대로 들은 학생이 내가
고른 자리를 못 맞혀 틀리게 된다. 건반은 화면 아래에 두고 눌러보기(소리만)로만 쓴다. 판 줄의 아이콘은
▤ 하나다.

로마숫자 **칸을 왼쪽부터 채운다.** 진행을 통째로 고르는 객관식은 보기가 여덟 줄을 넘으면 읽기 시험이
되고, 생김새로 지워 가며 풀린다. 칸 채우기는 보기 수가 늘지 않고 몇째 화음을 못 들었는지가 화면에 남는다.
맞은 칸은 초록으로 굳고 그 화음이 악보에 그려진다. 틀리면 그 칸만 잠깐 빨개지고 문제는 틀림으로 굳지만
칸은 밀리지 않는다(건반 채점과 같은 규칙). 틀리게 고른 것은 그 칸에 작게 남겨 무엇으로 착각했는지 보인다.

**조를 먼저 심는다** — 으뜸화음을 한 번 울리고 조 이름·조표를 보여 준다. 이게 없으면 머니코드의 돌린
꼴(`I–V–vi–IV`와 `vi–IV–I–V`)은 구별할 방법이 아예 없다.

로마숫자는 **그 조의 음계를 기준으로** 센다. 그래서 단조에서는 III·VI·VII에 ♭을 붙이지 않는다 —
숫자 앞의 ♭은 늘 "빌려 온 화음"이라는 표시다. `V/x`는 반드시 뒤에 `x`가 와야 하고, `II` 뒤에 `V`가 오면
그것은 `II`가 아니라 `V/V`다(소리가 같으므로 다음 화음까지 들어야 답이 나온다).

**보이스 리딩으로 자리를 잡는다.** 왼손은 뿌리음, 오른손은 앞 화음에서 손이 가장 덜 움직이는 자리를
고른다. 그래서 `I–IV–V–I`에서 첫 I과 끝 I의 자리가 다를 때도 있고 같을 때도 있다 — 실제 음악과 같다.
베이스도 같은 방법으로 고르되 뿌리음에 무게를 얹어(`BASS_ROOT_PULL`), 3음·5음으로 가는 편이 훨씬
매끄러울 때만 전위형이 된다. 첫 화음은 조를 세워야 하므로 늘 뿌리음이다. 왼손은 낮은음자리표에
앉도록 E2~A3에 두고 오른손은 그 위에 둔다 — 좁게 잡으면 옥타브가 하나뿐인 음이 생겨 베이스가
10도씩 뛴다.

난이도는 **칸 수 · 첫 칸을 찍어 주는지 · 로마숫자 후보 수 · 무엇을 가르는지** 넷으로 짠다. 한 판에서
한 가지만 바꾸고, `후보^칸수`를 판 순서 검사에 쓴다. **빠르게 들려주기, 화음 여덟 개, 조를 안 알려
주기는 쓰지 않는다** — 각각 반응 속도 시험, 기억력 시험, 다른 훈련이 된다. 판에 든 진행 가짓수는
난이도가 아니다(자루에서 다 나온다).

차용화음(modal interchange)은 **짝으로 낸다** — 같은 진행에서 IV와 iv를 번갈아 낸다. 물어보는 것은
도수가 아니라 **그 자리의 3음이 장3도인지 단3도인지**다. 로마숫자 판도 짝을 위아래로 나란히 놓는다
(빈 자리는 `null`로 비워 자리를 맞춘다). 팝에서 쓰는 것만 넣는다 — iv·♭VII·♭VI·♭III(나란한 단조),
단조에서 IV·ii(도리안)와 V(화성단음계), II(라이디언). ♭II·♯iv°는 만날 일이 없어 뺀다.

**「장조는 밝고 단조는 어둡다」는 말로 설명하지 않는다.** 음악의 성질이 아니라 흔한 비유일 뿐이고,
학생이 귀로 잡아야 하는 것은 3음이 반음 내려갔다는 사실이다.

노래 이름은 **과정 차시에만** 붙인다. 문제 화면에 박아 두면 틀린 분석이 그대로 오개념이 된다.

## 공통 설계 원칙

- 앱끼리 진도와 학습 기록을 섞지 않는다.
- 별도의 추천 또는 이어하기 화면을 만들지 않는다.
- 강제로 잠그는 단계를 두지 않는다.
- 제목 아래 곁말, 머리 이름표, 권유 문구를 넣지 않는다. 화면에 있는 말은 모두 문제를 푸는 데 쓰이는 말이어야 한다.
- 학생용 주요 조작은 44×44 CSS 픽셀 이상으로 만든다.
- 1024×768과 1180×820 가로 화면을 먼저 설계하고 768×1024 세로 화면과 좁은 세로 화면을 함께 지원한다.

```js
  setup: { interval: { level: "easy", mode: "harmony", items: [] } }
}
```
